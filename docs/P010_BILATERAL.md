# P0.10 — 양방향 원문 범위·직접 입력 우회 방지

## 구현 범위

기존 portfolio.html에 사업 A → B와 B → A의 원문 근거를 나란히 표시한다. 새 페이지, 계정, 데이터 저장소, 유료 API는 추가하지 않는다. 기존 계산식·월별 현금 모형·비용 및 인건비 중복 검사·대안 합산 차단은 유지한다.

- 기존 초기 일반형·초기 딥테크 2026 제한목록 검사를 보존한다.
- 예비창업 2026 제2026-207호 2차 수정 공고에서 초기 일반형·딥테크 두 상대 항목만 독립적으로 대조해 추가한다. 초기창업의 38개 명칭을 예비창업에 복사하지 않는다.
- 공고명을 알려진 사업으로 선택했으면 금액을 '직접 입력'으로 전환해도 해당 원본 확인·부분 제한 검사를 수행한다. 단일 직접 입력 사업이라도 연결된 원본이 오래되거나 실패하면 보류한다.
- 같은 사업명·사업연도의 금액 대안을 여러 사업 ID로 합산하는 입력을 검토 차단한다. 실제 다른 공고·차수라는 입증이 필요하며 법적 중복 수혜 위반으로 자동 단정하지 않는다. 일반 '다른 R&D'·'기타'·'지자체'를 동일 사업으로 뭉뚱그리지 않는다.
- 양쪽 원문이 존재하는 것, 해당 연도·상대 항목이 실제 대조된 것, 모든 적격성·예외를 검증한 것은 별개다. 2/2는 일부 조항의 방향별 대조 개수일 뿐 선정 확률·병행 허용·전체 검토 완료가 아니다.
- 공고 사업연도·상태 미입력과 종료 이력은 보류, 2027 이후는 별도 미확정 표시한다. 수행기간만으로 사업연도를 추정하지 않는다.

검토일: 2026-10-29. 공식 원본을 재다운로드해 기존 등록 지문과 대조했다.
위치: 인쇄 5쪽 신청 제외 ⑥; 인쇄 12쪽 동시수행 및 확약서 관련 주의; 13쪽 선정 후 확약서; 21쪽 붙임 3의 초기 일반형·딥테크 항목. 원본은 2쪽 모아찍기이므로 PDF 물리 페이지 번호와 인쇄 쪽 번호가 다르다.

예비창업의 과거 수혜 이력·모든 신청 예외·다른 기관 사업별 역방향·공고 수정본 탐색 전부를 검증한 것은 아니다. 첫 확약서의 실제 제출 순서도 입력받거나 증빙으로 확인하지 않는다. 그러므로 예외를 자동 적용하거나 전체 적격성 판정을 하지 않는다.

초기 일반형·딥테크는 P0.9의 공식 HWPX URL·지문과 부분 조항을 그대로 사용한다. 등록한 공개 데이터/config의 금액·자격을 이번 기능에서 수정하지 않는다. 원본 게이트는 StartupCore의 기존 프로그램 스냅샷·지문·최신 성공/실패·7일 제한을 재사용한다.

## 데이터 보호와 결과

입력은 현재 페이지 메모리에만 존재한다. 추가 fetch, 서버 쓰기, localStorage, sessionStorage, 개인 파일 업로드는 없다. 기존 공개 JSON 3개만 읽으며, 사용자가 명시적으로 클릭한 경우만 비공개 결과 JSON 또는 기관 확인 질문 TXT를 기기에 저장한다. 결과에는 두 방향의 출처·인쇄 쪽/구역 위치·SHA-256·검토 범위·미확정 상태가 포함된다. 입력 변경이나 근거 만료 시 이전 결과의 저장을 막는다.

## 검증 명령

- node --test scripts/test_portfolio_bilateral.cjs
- node --test scripts/test_portfolio_ui.cjs
- python -m unittest discover -s scripts -p test_portfolio_bilateral_contract.py -v
- 전체 기존 Python·Node·호환성 회귀시험과 scripts/build_public.py

새 시험은 수동 금액 우회, 단일 사업의 원본 보류, 반대 방향 누락, 과거/미래 사업연도, 상태별 보류, 중복 사업 식별, 3개 사업의 6개 방향, 공개 데이터 불변, 로컬 내보내기·개인정보 전송 방지를 검증한다. 브라우저 시각 검수와 운영 배포는 별도 실행 증거로 기록한다.

## 남은 범위

상대 사업의 모든 공고·예외, 공고별 인정 비목·지급·정산, 실제 2027 신규 공고 적용, 확약 제출 순서의 증빙 확인, 로그인 기반 공동 신청관리는 미완료다. 최적 지원금 조합·실제 확보액·병행 승인 기능으로 표시하지 않는다.
