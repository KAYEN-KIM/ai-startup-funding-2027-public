# P0.17 — 기관 후보 원문·첨부 근거 연결

## 이번 범위

P0.16의 중기부·NIPA 별도 목록 후보를 실제 공고 HTML과 연결하고, 현재
공고에 직접 연결된 PDF·HWP·HWPX를 기존 제한형 파서로 처리한다.
기존 공고 등록부, 검토된 자격·자부담·중복지원 규칙을 변경하지 않는다.
목록 후보를 수혜기업 공고로 자동 승격하거나 신청 준비 보드에 자동 추가하지 않는다.

- 실행: `python scripts/refresh_agency_evidence.py`
- 새 공개 기록: `data/agency_evidence.json`
- 새 보고서: `data/agency_evidence_report.md`
- 화면: 현황판 홈의 `#agencyEvidence`, 기존 직접 목록 영역 아래
- 정기 실행: 기존 23:00 UTC / 한국시간 08:00 일정 유지
- 모델 호출: 0. AI API·AI CLI·유료 서비스·새 인증키 없음

## 수집·검증 수준

회차당 원문 최대 3건, 파일 최대 4건을 처리한다. 두 기관에 순환 기회를
주며 최근 30시간 이내 성공한 목록에서 다시 관측된 후보만 선택한다.
목록 조회 실패·오래된 목록은 신규 다운로드의 근거로 삼지 않고 보존한다.
과거 마감·운영기관·용역·정책도 원문 연구 대상으로 포함될 수 있으므로
이 수치를 현재 신청 가능한 지원사업 수로 제시하면 안 된다.

현재 공고 제목은 중기부 `h4#sj`, NIPA `td.tbTit`의 제목을 목록과 대조한다.
본문은 중기부의 공고 편집 본문, NIPA의 '내용' 셀에서 추출한다. 조회수나
사이트 전체 메뉴를 본문 변경으로 오인하지 않도록 대상 구역만 지문을 만든다.
제목·구조가 다르면 보류하며 로그인·오류 페이지를 성공으로 취급하지 않는다.
HTML 렌더링, 표의 행·열 관계, 첨부의 완전성, 신청자격은 별도 검토 대상이다.

## NIPA 임시 다운로드 주소

실제 원문 재조회에서 `/comm/getFile`의 `upperNo`, `fileNo`가 매번 달라짐을
확인했다. 이 값을 해독·추측·고정하거나 공개 데이터에 저장하지 않는다.
현재 HTML에서 얻은 링크를 해당 실행의 메모리에만 두고 바로 사용한다.

NIPA 문서 참조는 공고 ID와 정규화한 파일명을 기준으로 만든다. 같은 이름의
서로 다른 링크가 한 공고에 여러 개 있으면 임의로 합치지 않고 보류한다.
파일명이 같아도 실제 바이트 지문을 재확인한다. 파일명 변경은 새 참조로
보존하며 옛 문서를 삭제하지 않는다. 이름 기반 참조는 파일 내용의 동일성이나
완전한 개정 이력을 보장하지 않는다. 화면의 NIPA 첨부 링크는 공고 원문으로
연결되며, 독자는 그 페이지의 현재 다운로드 링크를 사용한다.

중기부 다운로드는 현재 공고와 같은 `bcIdx`, 사업공고 `cbIdx=310`, 허용 파일
형식의 `streFileNm`을 요구한다. 다른 공고나 임의 경로의 파일을 다운로드하지 않는다.

## 보안·개인정보

HTTPS·정확한 호스트/경로·공고 ID·허용 매개변수·공개 DNS·robots 정책을 검사한다.
리디렉션도 같은 공고/같은 파일로만 제한한다. 로그인 세션·쿠키·인증정보는
사용하지 않으며 접근 거부·보호 문서·캡차를 우회하지 않는다.

파일은 8 MB, 파서는 기존 격리 프로세스와 30초 상한을 사용한다. PDF 암호화,
HWP 보호·DRM, 위험한 ZIP/XML, 지원하지 않는 형식은 처리하지 않는다.
OCR·매크로·스크립트·외부 XML 참조를 실행하지 않는다. 원본 바이트와 전체
본문은 임시로만 처리한다. 공개 결과는 기존 파서의 최대 24개 미검증 문구,
위치, 파일 지문과 제한 설명이다. 연락처 형태는 기존 마스킹을 사용한다.
회사정보·신청 원고·비공개 준비파일은 읽거나 서버에 보내지 않는다.

## 상태와 변경 보존

원문 열람과 첨부 본문 추출을 별도로 기록한다. 추출 성공은 자격 승인과 다르다.
원문 본문·첨부 목록·파일 바이트 변경은 검토 필요로 표시한다. 나중에 같은
파일을 다시 읽어도 이전 변경 검토 플래그를 자동으로 지우지 않는다.

실패하면 마지막 성공 근거를 남기고 최근 실패를 별도 표시한다. 기존 목록과
지문이 다르거나 재확인 상태가 나쁘면 화면은 과거 자료 가능성을 알린다.
미지원 링크, 부분 본문, 크기 제한, 다운로드 실패를 전체 성공으로 합치지 않는다.
기존 P0.15 일일 보고/RSS의 범위와 이번 독립 근거 보고의 상태는 별개다.

## 운영 연결

수집은 일정/수동 전체 실행에만 추가된다. 코드 push는 수집을 재실행하지 않는다.
명시적 공개 파일 allowlist와 중첩 스키마 검사를 통과한 결과만 배포한다.
실패 기록도 배포할 수 있지만 최종 workflow는 해당 단계 실패를 숨기지 않는다.
기존 설정·자격 규칙·사업화 한도·회사 입력 저장방식은 보존한다.

## 시험

- `python -m unittest discover -s scripts -p test_agency_evidence.py -v`
- `node --test scripts/test_agency_evidence_ui.cjs`
- 전체 기존 Python/JavaScript/호환성 회귀시험 유지

신규 시험은 원문 제목·파일 연결, 임시 주소 변화, 접근 거부, 정책 차단,
이전 성공 보존, 변경 플래그, 문서 한도, 입력 외부 전송 금지, 화면 실패 표현을
검사한다. 실제 브라우저 시각 검수 여부는 인수 기록에서 별도로 보고한다.
