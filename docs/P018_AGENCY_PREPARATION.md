# P0.18 — 기관 후보에서 신청 준비로 연결

## 구현 범위

기관 목록과 근거를 공개 등록 공고와 분리한 채, 기존 applications.html의 개인 준비 기록으로 연결한다. 새 페이지·백엔드·AI 호출·AI CLI·유료 API·자동 신청은 추가하지 않는다. 일일 수집 예약과 이미 중지된 ChatGPT 예약 작업은 변경하지 않는다.

- 홈의 기관 목록·근거 카드에서 `검토 후보로 준비하기`를 누르면 공개 ID만 해시로 전달한다. 후보 선택만 하고, 사용자가 추가 버튼을 눌러야 보드에 기록한다.
- 보드의 `기관 후보·근거 불러오기`는 공개 목록과 공개 근거 JSON만 읽는다. 평상시의 기존 두 파일 읽기는 유지한다. 기관 후보 연결 요청 시 총 네 개의 고정된 공개 GET 경로만 사용하고 credentials를 생략한다. 사용자 문안·회사정보·작업 내용은 요청에 넣지 않는다.
- 기관 후보는 페이지 메모리의 공고 목록에만 투영한다. `data/programs.json`이나 검토 규칙에 저장·병합·승격하지 않는다.
- `candidate` 분류와 단일 명시 사업연도가 있는 후보만 새 준비 대상으로 제공한다. 운영기관·용역·정책·공모전·결과 발표는 제외한다. 미표기·복수 사업연도는 추정하지 않는다.
- MSS의 cbIdx/bcIdx, NIPA의 bbsNo/nttNo에 따른 같은 공식 공고 식별자는 기존 등록을 선택한다. 호스트 www 및 NIPA 목록 경로 표현 차이는 정규화한다. 제목만 같거나 목록에 matched_program_ids가 있다는 이유로 합치지 않는다. 같은 식별자에 기존 등록이 여러 개면 대조를 요구한다.
- 모든 새 투영은 `discovery` 상태다. 원문·첨부 본문을 읽었어도 신청자격·공식 필수서류·선정·지원금으로 승인하지 않는다. 합산 확보액도 만들지 않는다.

## 기존 준비파일 호환성

기존 private-funding-applications/v3 형식을 유지한다. v1/v2 파일은 기존 복원 경로를 그대로 사용한다. 새 후보는 `AGENCY-기관ID`를 사용하고, 기존 reference.source_level 필드에 짧은 공개 근거 기준(목록/본문/첨부 목록/파일 SHA-256)을 보관한다. 본문 전체나 임시 다운로드 URL을 저장하지 않는다.

원본 지문 변경은 기존 표시 정보 차이 및 문서 대조 무효화 체계에 연결한다. 시각만 새로 확인됐거나 첨부 나열 순서만 바뀌면 자료 변경으로 오인하지 않는다. 현재 목록에서 사라지거나 연도·분류가 달라져도 저장된 작업과 문안은 보존한다. 합쳐진 기존 등록으로 기존 사용자 작업을 자동 이전하지 않는다.

기관 후보가 들어 있는 준비파일을 사용자가 확인 후 불러오면, 고정된 공개 기관 파일을 재조회한다. 파일의 URL을 네트워크 대상으로 사용하지 않는다. JSON은 비공개·비암호화이며 자동 저장하지 않는다. 새로고침 전에 명시적으로 저장해야 한다.

## 확인 상태와 일정

기관별 마지막 목록 성공(30시간), 마지막 관측 포함 여부, 목록 지문, 원문 성공, 첨부 상태·내용 변경을 별도 패널에서 표시한다. 기업마당 수집 성공으로 기관 원문 실패를 가리지 않는다. 재조회 실패 시 이전 자료를 보존하고 과거 기록일 수 있음을 표시한다. 미확인·실패·제한 첨부를 해결됐다고 하지 않는다.

후보의 기재 마감은 공식 캘린더 일정에 넣지 않는다. 사용자가 직접 설정한 내부 작업일·목표일만 내보낸다. 기존 검증 공고의 일정 규칙은 유지한다. 자료·표시값을 확인했다고 누르는 것은 사용자의 자체기록일 뿐, 원문 검증이나 공식 승인이 아니다.

초안·제출 전 TXT에는 그 시점의 기관 근거 경고를 덧붙인다. 서류 원본을 읽거나 자동 제출하지 않는다.

## 검증 명령

```
node --test scripts/test_application_agency.cjs scripts/test_application_agency_ui.cjs
node --check assets/application-agency.js
node --check assets/applications-ui.js
python scripts/build_public.py
```

두 신규 시험 파일은 63개 규칙·VM/DOM 시험을 포함한다. 전체 기존 회귀시험도 별도 실행한다. VM/DOM 시험은 실제 브라우저 시각 검수와 구분한다. 새 JS/CSS는 public build의 명시적 파일 목록에만 추가한다.

## 남은 범위

공식 제출양식 자동 기입, 개인 적격성의 완전한 판정, 자동 지원 신청, 클라우드 공동편집, K-Startup/KOCCA 직접 수집은 이 변경에 포함하지 않는다. 기본 공고와 기관 공고가 서로 다른 중계 URL을 쓰는 경우는 동일 사업 자동 병합을 하지 않는다. 목록에서 연도가 확인되지 않은 후보는 추가 원문 검토 이후 연결할 수 있다. 과거 수집 실패와 미처리 첨부의 해소도 이번 기능 배포만으로 완료되지 않는다.
