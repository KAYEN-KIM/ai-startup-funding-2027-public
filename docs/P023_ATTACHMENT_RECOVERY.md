# P0.23 — 정부지원사업 첨부 복구·재시도 봇

## 목표

정기 수집은 신규 첨부와 과거 전송 오류를 분리하여 **최대 4개**의 파일만 처리한다.
AI 모델·AI API·유료 검색 호출을 하지 않는다. 이전 실패 기록이나 이미 수집한
첨부의 원본·해시·추출 근거는 지우지 않으며, 오류가 난 파일을 성공으로 승격하지 않는다.

## 오류별 실행 정책

| 현재 상태 | 정책 | 예외 |
| --- | --- | --- |
| queued | 신규 파일 우선순위로 처리 | 현재 공고의 공개 링크가 유지돼야 함 |
| download_failed + retryable 네트워크 오류 | 시차 재시도 | 60분부터 성공 전 최대 48시간 대기 |
| HTTP 408/429/500/502/503/504 + retryable true | 시차 재시도 | 서버 과부하·요청 제한 시 재대기 |
| HTTP 401/403/404 | 자동 재시도 금지, 원문 직접 확인 | 인증·접근 정책 우회 금지 |
| 손상·비지원·보호·크기 초과 | 자동 재시도 금지 | 원문·형식·처리기 검토 |
| partial_text/no_text | 자동 성공 판정 금지·원문 대조 | OCR/이미지/표를 임의로 추론하지 않음 |
| text_extracted | 14일 경과 후 순환 재확인 | 실적·적격성 검증은 별도 |
| 현재 공고와 링크가 연결되지 않음 | 자동 다운로드 금지 | 과거 기록은 보존 |

실패 이력의 연속 횟수에 따라 대기시간이 60분, 240분, 1440분, 2880분으로
증가하며, 성공 이력이 있어도 실제 새 파일을 추출하기 전에는 성공·검토
완료로 바꾸지 않는다.

회차당 신규와 재시도 후보가 모두 있으면 재시도 1개를 우선 예약하고,
나머지 최대 3개는 신규 파일을 처리한다. 후보가 부족하면 미사용 슬롯을
다른 재시도/오래된 성공 자료 재확인에 사용한다. 원문 검색은 최대 3건,
첨부파일 처리는 최대 4건이며, 다운로드/파서 별도 기존 제한은 유지한다.

## 관측·배포

- 새 자료: data/attachment_recovery.json
- 생성: scripts/attachment_recovery.py. 기존 attachments.json의 공식 기록만 읽는 결정론적 함수.
- 화면: 홈 → 첨부파일 복구·재시도 운영. 신규·재시도·대기·수동검토·오래된 성공 자료를 구분.
- 원문 URL 토큰/바이너리/원문 텍스트/개인 지원정보를 대기열에 담지 않는다.
- 결과가 이전 첨부 수집 실행을 반영하는 시각인지 명시한다. 기능 코드 배포는 수집 실행과 구분.
- 실패한 HTTP 권한/지원불가 형식 파일을 자동으로 다운로드 반복하지 않는다.
- 기존 기업마당 API·중기부·NIPA 수집 범위, 수동 검증 규칙은 그대로 보존한다.

회귀시험은 전체 Python, JavaScript 및 기존 호환성 시험과 함께 GitHub Actions 검증을 통과해야 한다.

## 유의사항

과거 3건의 전송 오류가 자동으로 해결됐다고 간주할 수 없다.
재시도에서 다시 실패하면 원래 실패를 유지하고 사유·시각을 갱신한다.
수집이 성공해도 원문 적격성·예산·중복지원·공식 제출요건이 검증되는 것은 아니다.
