# P0.7 — 월별 현금흐름과 독립 대안 비교

기준 부모: `4b5f995a1348b33166c24ba240d0c4f0439b7234` (P0.6).

## 구현 범위

- `cashflow.html`: P0.6의 2026 참고 경로 3개·지역/단계 계산식 9개를 그대로 사용한다. 새 2027 규칙이나 새 지원 한도를 만들지 않는다.
- 1~24개월의 원 단위 현금 일정. 화면은 6/12/18/24개월을 제공한다.
- 동일한 프로젝트 지출에 대해 지원금 없음, 가정 일정, 0~12개월 지연을 각각 계산한다.
- 최초 가용 현금, 월별 매출 입금/운영비, 사업 현금 지출, 지원금 입금, 투자/차입/원금상환/이자/추가 지출/추가 매출을 구분한다.
- 현물, 보증, 세액공제는 현금 유입으로 계산하지 않는다. 기초 차입원금도 현금에 다시 더하지 않는다.
- 최저 가용 잔액, 처음 음수가 되는 달, 목표 현금까지 최대 부족액, 기간 밖 지급액, 제한된 지원금 잔액을 제공한다.
- 최대 3개의 독립 대안을 현재 페이지 메모리에 보관해 비교한다. 합산, 순위, 선정확률 또는 병행 허용을 계산하지 않는다.

## 분석 가정과 회계 항등식

G = 요청 지원액 가정, O = 기존 규칙 엔진이 산출한 필요 자부담 현금.
사업비 현금 총액 C = G + O. 현물과 O를 다시 지출로 더하지 않는다.

매월까지 누적 사업 현금 지출 X에 대해 가정상 누적 지원금 사용가능 한도는
`floor(X * G / C)`이다. 누적 지원금 수령액을 R이라 하면 누적 환입 U는
`min(R, floor(X * G / C))`이다. 제한 지원금은 `R - U`이다.

가용 현금 월말 = 월초 가용 현금 + 매출 입금 + 투자 + 차입 + 당월 환입
- 운영비 - 사업비 현금 지출 - 추가 지출 - 원금상환 - 이자.

이 비례 환입은 **분석 모델의 가정**이다. 해당 지원사업의 실제 비용 인정,
정산, 선지급/후지급, 직접지급, 전용 계좌와 일반 계좌 간 이체 권리를 의미하지 않는다.
미사용 지원금은 가용 운영자금과 별도 표시한다. 원문과 실제 협약을 별도로 확인해야 한다.

최대 부족액은 각 달 부족액의 합계가 아니라 전 기간 `max(목표현금 - 가용잔액, 0)`이다.
월중 지급 순서를 모르므로 월중 최대 부족액은 계산하지 않는다. 원금은 입력한 기초 잔액과
동월까지의 신규 차입을 초과하여 상환할 수 없다. 이자율을 가정해 이자를 자동 생성하지 않는다.
모든 미래 입금(매출·투자·대출 포함)은 사용자 가정이다. 선택되지 않은 지원금을 확정액으로 표시하지 않는다.

## 입력·자료 보호

- 초기 로드와 사용자가 누른 공개 근거 재조회에서만 `startup_routes.json`, `programs.json`, `startup_sources.json`을 GET한다.
- 자금 입력은 외부 전송, 자동 저장, 쿠키·로컬스토리지·서비스워커·분석 서비스 사용 없이 메모리에서만 처리한다.
- 사용자가 누른 저장 버튼만 `private-cashflow-plan-export/v1` JSON을 로컬 다운로드한다. 이 파일은 공개 저장소로 업로드하지 않는다.
- 입력/일정/경로가 바뀌면 계산과 저장을 무효화한다. 이벤트 없이 값만 달라져도 저장 직전에 재검사한다.
- 기존 `StartupCore.gate`의 원본 지문·스냅샷·7일 재확인 제한을 재사용한다. 저장 직전에도 다시 검사한다.
- 예시는 가상 데이터다. 실명·사업자번호·은행·실제 사내 자료를 읽지 않았다.

지급·제한자금·원금 초과 상환·미입력·오래된/변경된 원문·독립 대안과 개인정보 보호를 포함한다.
VM/DOM 시험은 실제 브라우저 시각 검수와 다르다. 실제로 하지 않은 검수는 완료로 기록하지 않는다.
